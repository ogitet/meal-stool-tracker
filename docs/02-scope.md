## 1. スコープの考え方

- 判断基準は Strategy 第2版の G1（減らしたいものを食べる日を減らす）を最優先とする。
- 記録の種類は「減らしたいもの」「続けたいこと」「便」の3つとする。
- 減らしたいもの・続けたいことは、「起きた日に、起きた項目を押す」だけの記録とする。量・回数・時刻は持たない。
- 押さなかった日は、減らしたいものは無事故、続けたいことはやっていない、とみなす（Strategy Q44）。
- 便は初版の要件をそのまま引き継ぐ。

### 用語

| 用語 | 意味 |
|---|---|
| 減らしたいもの | 食べる日を減らしたいものの集まり。1つだけ持つ。初期の項目はパンとお菓子 |
| 続けたいこと | 毎日続けたいことの集まり。1つだけ持つ。初期の項目は運動 |
| 項目 | 減らしたいもの・続けたいことの中身（パン、お菓子、運動など）。利用者が決める |
| 食べた日 | 減らしたいもののいずれかの項目を記録した日 |
| 無事故の日 | 起点日以降で、食べた日でない日（今日を含む） |
| やった日 | 続けたいことのいずれかの項目を記録した日 |
| 起点日 | 無事故を数え始める日（→Q52） |

## 3. 機能要件

### F-12 減らしたいものの記録

| # | 要件 |
|---|---|
| 1 | 減らしたいものの項目から、食べたものを選んで記録できる |
| 2 | 記録は「日付 × 項目」とし、同じ日の同じ項目は1件とする。1日に何回食べたかは数えない →Q51 |
| 3 | 1日に複数の項目を記録できる |
| 4 | 今日の分は日付の入力なしで記録できる。過去の日の分も記録できる（押し忘れへの対応） |
| 5 | 未来の日には記録できない |
| 6 | 量・時刻は入力しない。作成日時のみ自動で保持する |
| 7 | 押さなかった日は無事故とみなす（Strategy Q44）。起点日より前の日は対象外とする →Q52 |

### F-13 続けたいことの記録

| # | 要件 |
|---|---|
| 1 | 続けたいことの項目から、やったものを選んで記録できる。項目が1つだけなら、選ぶ操作を省く |
| 2 | 記録は「日付 × 項目」とし、同じ日の同じ項目は1件とする |
| 3 | 今日の分は日付の入力なしで記録できる。過去の日の分も記録できる。未来の日には記録できない |
| 4 | 時間・距離などの内容は入力しない。作成日時のみ自動で保持する |
| 5 | 押さなかった日は、やっていない日とみなす |

### F-03 便記録（初版から維持）

| # | 要件 |
|---|---|
| 1 | 排便ごとに記録でき、1日に複数回記録できる |
| 2 | 形状（硬い／普通／柔らかい／下痢）を1つ選んで記録する |
| 3 | 量（少／普通／多）は任意で記録できる |
| 4 | 排便感（すっきり／残便感あり）は任意で記録できる |
| 5 | 記録時刻は自動取得する |
| 6 | 過去の日付の分も記録できる（記録し忘れへの対応） |
| 7 | 過去の日付に追加した場合、日付はその日、時刻は記録操作時の時分を初期値とする →Q5 |

### F-10 月カレンダー

| # | 要件 |
|---|---|
| 1 | 起動直後の画面とする。週表示は設けない →Q56 |
| 2 | 前後の月に移動でき、今日を含む月に戻れる |
| 3 | 日ごとに、食べた項目の印、やった項目の印、便の記録（排便1回につき1つ、形状がわかる形）を示す |
| 4 | 起点日以降の日について、食べた日と無事故の日を一目で区別できる |
| 5 | やった日を一目で判別できる |
| 6 | 今日の日付を視覚的に強調する |
| 7 | 日付を選択すると、その日の詳細を確認できる。未来の日は選択できない |
| 8 | 週の開始曜日は月曜とする →Q13 |
| 9 | 画面の上部に、F-14 の数字を常に示す |
| 10 | 減らしたいもの・続けたいこと・便の記録を、この画面から1タップで始められる |

### F-14 連続日数と月の日数

| 対象 | 数字 | 定義 |
|---|---|---|
| 減らしたいもの | 今月の食べた日数 | 今月1日から今日までの、食べた日の数 |
| | 先月の同じ時点 | 先月1日から先月の同じ日までの、食べた日の数 →Q54 |
| | 無事故の連続日数 | 最後に食べた日の翌日から今日までの日数（今日を含む）。今日食べていれば0。起点日以降に一度も食べていなければ、起点日から数える →Q55 |
| | 自己ベスト | 起点日以降で最も長かった、無事故の連続日数（今続いている分を含む） |
| 続けたいこと | 連続日数 | やった日が続いている日数。今日まだやっていなければ、昨日までで数え、途切れとしない →Q55 |
| | 自己ベスト | 最も長かった連続日数（今続いている分を含む） |
| | 今月のやった日数 | 今月1日から今日までの、やった日の数 |

| # | 要件 |
|---|---|
| 1 | 上の数字を、記録・取り消しのたびにすぐ反映する。過去の日への記録や取り消しでも計算し直す |
| 2 | 減らしたいものは、月の日数を主役とし、無事故の連続日数と自己ベストを添える（Strategy Q47） |
| 3 | 続けたいことは、連続日数を主役とし、自己ベストと今月の日数を添える |
| 4 | 連続日数が途切れたときも、自己ベストと月の日数は残る（Strategy 原則3） |

### F-05 日別詳細

| # | 要件 |
|---|---|
| 1 | 選択した日に食べた項目、やった項目、便の記録を確認できる |
| 2 | 選択した日に、減らしたいもの・続けたいこと・便の記録を追加できる（過去の日の記録） |
| 3 | 減らしたいもの・続けたいことの記録を取り消せる |
| 4 | 便の記録の編集・削除に進める |

### F-06 記録の取り消し・編集・削除

| # | 要件 |
|---|---|
| 1 | 減らしたいもの・続けたいことの記録は編集せず、取り消しと押し直しで直す |
| 2 | 減らしたいもの・続けたいことの取り消しは確認を求めない。取り消したことを知らせ、元に戻せるようにする →Q53 |
| 3 | 便の記録は編集でき、日時も修正できる →Q5 |
| 4 | 便の記録の削除は、誤操作を防ぐ確認を経て実行する（バックアップがないため） |

### F-07 本人のみのアクセス（初版から維持）

| # | 要件 |
|---|---|
| 1 | 本人以外はデータを閲覧・変更できない |
| 2 | 利用者は本人1名のみとし、一般向けの新規登録は設けない |
| 3 | 一度ログインすれば、通常の利用では毎回のログインを求めない |

### F-08 スマホ向けPWA（初版から維持）

| # | 要件 |
|---|---|
| 1 | スマホの画面サイズに最適化する。PC向けの最適化は行わない |
| 2 | スマホのホーム画面に追加して起動できる |
| 3 | オフラインでも記録できる。記録は端末に保存し、通信が戻ったときに自動で同期する。未同期の記録があることを画面で示す →Q14 |

### F-15 項目の管理

| # | 要件 |
|---|---|
| 1 | 減らしたいもの・続けたいことのそれぞれに、項目を追加できる。各4つまでとする →Q57 |
| 2 | 項目の名称と略称（1文字、カレンダーの印に使う）を変更でき、過去の記録にも新しい名称が表示される →Q7 |
| 3 | 項目は削除せず「使わない」状態にする。選択肢には出なくなるが、過去の記録には残り、食べた日・やった日として数え続ける →Q58 |
| 4 | 減らしたいもの・続けたいことそのものを増やしたり、名前を変えたりはしない →Q59 |

### F-16 初版の食事記録の引き継ぎ

| # | 要件 |
|---|---|
| 1 | 初版の食事記録のうち、カテゴリ「パン」を含む日を項目「パン」、お菓子グループ（菓子パンを含む）のカテゴリを含む日を項目「お菓子」の記録にする |
| 2 | 引き継ぎは1回だけ行う。初版の食事記録は画面に出さなくなるが、データは消さない |
| 3 | 引き継いだ場合の起点日は、初版の食事記録の最初の日とする →Q52 |

## 4. 品質要件

| 観点 | 要件 |
|---|---|
| 入力の速さ | 減らしたいもの：2タップ以内（開始 → 項目）。続けたいこと：項目が1つなら1タップ。便：約5秒（初版） |
| 何も起きない日 | 操作は不要（0タップ） |
| 表現 | 食べた日を、警告や叱責として示さない。食事・運動と便の関係について、因果関係の断定や医学的な判断・助言をしない |
| 運用コスト | クラウドサービスの無料枠の範囲で運用できる |
| 日付の区切り | 端末の暦日（0時）で区切る。深夜に食べた分を前日にしたい場合は、日付を選んで記録する →Q16 |

## 7. 判断事項

### 初版から維持

| # | 問い | 決定 |
|---|---|---|
| Q5 | 便の記録時刻を後から修正できるか | できる。便の日時を編集で修正する。記録時には時刻の入力を求めない |
| Q7 | 項目（初版はカテゴリ）を変更・削除したとき、過去の記録をどう扱うか | 名称変更は過去にも反映する。削除の代わりに「使わない」状態にして過去の記録を残す。意味が変わる改名は数字を歪めるため、その場合は新しい項目を追加する |
| Q9 | 「その日の便」をどう定義するか | 定義しない。日付と日時を残し、分析機能を作るときに決める |
| Q13 | 週の開始曜日 | 月曜（月カレンダーの列の並び） |
| Q14 | オフラインでの記録に対応するか | 対応する。記録は端末に保存してすぐ画面に反映し、通信が戻ったときに自動で同期する。未同期の記録があることを画面で示す |
| Q16 | 1日の区切りをいつにするか | 暦日（0時） |

食事記録の廃止に伴い、Q6（食事の時刻）、Q8（コピーの対象）、Q10（カテゴリなしの保存）、Q11（食事枠の件数）、Q12（週カレンダーの粒度）、Q15（カテゴリ管理の範囲）、Q29（間食）、Q38（食事カテゴリの分類）は対象がなくなった。

### 第2版で追加（2026-11-25）

| # | 問い | 決定 | 理由 |
|---|---|---|---|
| Q51 | 1日に何回食べたかを数えるか | 数えない。同じ日の同じ項目は1件 | 減らす単位を「日」にそろえる。回数を入れると、食べるたびに押す手間が増える |
| Q52 | 無事故をいつから数えるか | 起点日から数える。起点日は、減らしたいものの記録を始めた日とする。初版の食事記録を引き継いだ場合（F-16）は、その最初の日とする | 使う前の日まで無事故とみなすと、数字が実際より大きくなる |
| Q53 | 減らしたいもの・続けたいことの取り消しに確認を求めるか | 求めない。取り消したことを知らせ、元に戻せるようにする | 押し直せば失うものがない。押し間違いはすぐ直したい |
| Q54 | 先月と何を比べるか | 先月の同じ日までの食べた日数。先月に同じ日がなければ先月末まで | 月の途中でも公平に比べられる。月全体と比べると、月初めは必ず少なく見える |
| Q55 | 今日をどう数えるか | 無事故は今日を含めて数え、今日食べたら0にする。続けたいことは、今日まだ押していなくても途切れとせず、昨日までで数える | どちらも、その日が終わるまでは続いている途中として扱う |
| Q56 | 週カレンダーを残すか | 残さない。月カレンダーを起点の画面にする | 記録する日がまばらになり、1日分の印が少ないため、月表示で十分に判別できる。初版で週表示が必要だったのは、食事の印が1日に十数個並んだため |
| Q57 | 項目をいくつまで持てるか | 減らしたいもの・続けたいことの、それぞれ4つまで | 月カレンダーの1マスに収める。一度に変えようとする対象を増やしすぎない |
| Q58 | 「使わない」にした項目の過去の記録を数えるか | 数える | 食べた日・やった日という過去の事実は変わらない。数えなくすると、過去の数字が後から変わる |
| Q59 | 減らしたいもの・続けたいことを複数持てるか | 各1つで固定する。中身は項目で調整する | 守る数字を1つにする（Strategy Q46）。複数持つことは将来の検討対象とする |
