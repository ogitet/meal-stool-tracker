## 1. プロダクトの一文定義

**自分で決めた「減らしたいもの」と「続けたいこと」だけを判子で残し、カレンダーと連続日数で、習慣が変わるまで伴走する個人用アプリ。あわせて、便の記録を続ける。**

食べたものを網羅的に残す道具ではない。記録するのは、自分で決めたことが起きた日だけである。何も起きない日は、何もしなくてよい。

---

## 2. 初版で分かったこと

初版は「食事と便を数タップで記録し、カレンダーで振り返って傾向に気づく」ことを目的にした。約2週間使って、次のことが分かった。

| 分かったこと | 意味 |
|---|---|
| 食事の記録は毎日ほぼ同じ内容になった | 傾向はすでに分かっていた。記録しても新しい気づきが生まれない |
| 傾向に気づいても、行動は変わらない | 足りないのは気づきではなく、「何を変えるか」を先に決めることと、それができたかが毎日返ってくること |
| 便の記録には価値を感じている | 便は観察そのものが目的であり、初版の形のまま続ける |

本当に解決したかった課題は、**体に悪いと思いながら食べてしまうもの（悪習慣）を減らし、運動などの良い習慣を続けること**である。健康のために大事だと考えている睡眠・食事・運動のうち、睡眠は気に入っている専用アプリがあるため、このアプリでは食事と運動を扱う。

## 3. ユーザーニーズ

### 対象ユーザー

自分自身のみ（開発者＝利用者）。他者への提供は考慮しない。

### 利用の文脈

| 場面 | 状況 | 求めていること |
|---|---|---|
| 減らしたいものを食べてしまったとき | 少し気が重い。手短に済ませたい | 責められずに、数タップで残せる |
| 運動したとき | 達成した直後 | 1タップで押せて、続いていることが見える |
| 排便後 | その場ですぐ記録したい | 形状を選ぶだけで終わる |
| 食べたくなったとき | 誘惑の直前 | 開いた瞬間に「何日続いているか」が目に入る |
| 何も起きない日 | アプリを開く理由がない | 何もしなくても記録が正しく進む |
| 振り返るとき | 月の途中や月末 | 食べた日と運動した日を、月単位で一目で見渡せる |
| 記録し忘れたとき | 後から思い出す | 過去の日に気軽に押せる |

### 満たすべきニーズ

1. **減らしたいものを食べた日が一目でわかること**：いつ食べ、いつ食べなかったかを月単位で見渡せる
2. **減っていることが実感できること**：先月と比べて減ったかがわかる
3. **続けたいことが続いているとわかること**：連続日数で、途切れさせたくない気持ちを後押しする
4. **途切れても戻ってこられること**：一度食べた、一日休んだだけで、積み上げが消えたように感じさせない
5. **便の傾向が見えること**：形状や回数の推移がわかる（初版から維持）
6. **記録の負担がほぼないこと**：何も起きない日は0タップ、起きた日も数タップ

## 4. プロダクト目標

| # | 目標 | 位置づけ |
|---|---|---|
| G1 | 減らしたいものを食べる日を減らす | **最優先** |
| G2 | 続けたいこと（運動）を毎日続ける | 優先 |
| G3 | 便の記録を続け、傾向を見られる状態を保つ | 初版から維持 |

記録すること自体は目標ではない。G1・G2 のための最小限の手段として扱う。

### 成功の判断基準

個人利用のため、厳密なKPIは置かず、次の問いに実感で答えられるかで判断する。数値は目安であり、使いながら見直す。

| 目標 | 判断の問い | 目安 |
|---|---|---|
| G1 | 減らしたいものを食べた日は、減っているか | 使い始めた月より、食べた日数が少ない月が続く |
| G1 | 食べたくなったとき、数字を思い出して踏みとどまれたことがあるか | 実感としてある |
| G2 | 運動を続けられているか | 1か月のうち8割以上の日に運動した |
| G1・G2 | カレンダーを開いて、今月の様子を言葉にできるか | 日別の詳細を開かずに「今月は食べたのが5日、運動は25日」と言える |
| 全体 | 記録が負担になっていないか | 何も起きない日は0タップ。記録は1回2タップ以内 |

## 5. 設計原則

判断に迷ったときの基準。上にあるものほど優先する。

1. **決めたことだけを記録する**：食べたものの網羅、カロリー、量、時刻は記録しない
2. **何も起きない日は0タップにする**：押さなかった日は「食べなかった日」（減らしたいもの）、「やっていない」（続けたいこと）とみなす（Q44）
3. **途切れても戻れるようにする**：連続日数には、自己ベストや月の日数のように、途切れても消えない数字を必ず添える
4. **良し悪しは自分で決める**：何を減らし、何を続けるかは利用者が決める。アプリは食品や行動の良し悪しを判断しない
5. **責めない、ただし励ます**：食べた日は事実として示し、警告や叱責の表現にしない。続いていることは数字で励ます
6. **過剰につくらない**：個人利用に見合う複雑さに留め、使いながら改善する

加えて、次の点を全体の姿勢とする。

- **因果関係を断定しない**：食事・運動と便の関係は傾向として扱い、医学的な判断や助言はしない

## 6. 戦略上のスコープ境界

詳細な機能要件は Scope レイヤーで定義する。ここでは方向性のみを示す。

| 扱う | 将来の検討対象 | 扱わない |
|---|---|---|
| 減らしたいものを食べた日の記録 | 月ごとの数値目標（例：月10日まで） | 食べたものの網羅的な記録（初版の食事記録） |
| 続けたいことをやった日の記録 | 減らしたいもの・続けたいことを複数持つこと | カロリー・栄養素・量 |
| 便の記録（初版から維持） | 通知（夜の振り返りの声かけなど） | AI・写真による記録、食品データベース |
| 月カレンダー、日別詳細 | | 睡眠の記録（専用アプリに任せる） |
| 連続日数、自己ベスト、月の日数 | | ヘルスケア（HealthKit）との連携。PWA からは使えない |
| 項目の管理 | | SNS・ユーザー共有 |
| 初版の食事記録からの引き継ぎ | | バックアップ・エクスポート |

提供形態は、スマホで使う個人利用のWebアプリ（PWA）とし、初版と同じく無料で使えるクラウドサービスに保存する。

## 7. 主なリスク

| リスク | 影響 | 方針 |
|---|---|---|
| 食べた日に押し忘れ、食べなかった日の数が実際より多くなる | 数字が信頼できなくなる | 過去の日にも押せるようにする。押し忘れが続くようなら、毎晩「今日は食べなかった」を押す方式（Q44 の案B）に切り替える |
| 連続日数が途切れて、投げ出してしまう | G1・G2 が崩れる | 自己ベストと月の日数を併記し、積み上げが消えたように見せない（原則3） |
| 何も起きない日にアプリを開かず、目標が意識から薄れる | 誘惑に負けやすくなる | 運動を毎日押すために開く。開いた瞬間に数字が目に入る配置にする |
| 食べた日の表示が責めているように感じ、開くのが嫌になる | 記録が止まる | 警告色や否定的な文言を使わない（原則5）。表現は Surface で決める |
| 自分で決めた良し悪しを、医学的な判断と受け取る | 誤った自己判断につながる | アプリは判断せず、断定を避けた表現にする |
| 排便などの機微な情報が外部に漏れる | プライバシーの侵害 | 初版と同じく、本人以外がデータにアクセスできない構成にする |
| 無料枠の条件変更やサービス終了 | 記録を使えなくなる、または失う | バックアップを持たないことは受容する |

## 8. 判断事項

### 初版から維持

| # | 問い | 決定 |
|---|---|---|
| Q1 | データをどこに保存するか | 無料で使えるクラウドサービス（Firebase。06-tech） |
| Q2 | 利用する端末はどれか | スマホのみ |
| Q3 | データのバックアップやエクスポートは必要か | 不要 |

### 第2版で変更・追加（2026-11-25）

| # | 問い | 決定 | 理由 |
|---|---|---|---|
| Q4 | 記録の抜けと「該当なし」を区別するか（変更） | 区別しない点は同じ。ただし初版の「未記録として断定しない」をやめ、押さなかった日を「食べなかった」「やっていない」と言い切る（Q44） | 連続日数を出すには、押さなかった日に意味を持たせる必要がある |
| Q44 | 押さなかった日をどう扱うか | 減らしたいものは、食べた日だけ押す（案A）。押さなかった日は食べなかった日とみなす。毎晩「今日は食べなかった」を押す方式（案B）は採らない | 何も起きない日を0タップにでき、「毎日同じ記録」の徒労がなくなる。工事現場の「無事故◯日」の看板と同じく、日は自然に進み、食べた日だけ戻る。案Bは毎晩思い出させる通知がないと抜けが増えるが、今の構成（サーバーなし・無料枠）では通知の追加が大きい |
| Q45 | 何を対象にするか | 食事（減らしたいもの）と運動（続けたいこと）、便。睡眠は扱わない | 健康に大事な3つのうち、睡眠は専用アプリで満たせている |
| Q46 | 減らしたいものをいくつに分けて数えるか | パンとお菓子を1つにまとめ、どちらかを食べた日を「食べた日」とする | 1つの数字を守るほうが分かりやすい。項目は判子の表示に使う |
| Q47 | 断つのか、減らすのか | 減らす。そのため、主役は月の食べた日数（先月の同じ日までとの比較）とし、食べずに続いた日数と自己ベストを添える | 減らすことが目標なら、1回食べたら0に戻る連続日数より、月の日数のほうが進み具合を正しく表す |
| Q48 | 続けたいことの頻度 | 毎日。連続日数は日単位で数える | 毎日の運動を目標にしている |
| Q49 | 初版の食事記録をどうするか | 画面から外す。過去の記録は消さず、パンとお菓子を含む日を「食べた日」として引き継ぐ | 記録の網羅に価値を感じなかった。引き継げば、使い始めから月の日数と連続日数が出せる |
| Q50 | 便の記録をどうするか | 初版の機能とカレンダー表示を維持する | 観察そのものに価値を感じている |

## 9. 初版からの変更

| 初版 | 第2版 |
|---|---|
| 目的は記録を続けること（G1） | 目的は習慣が変わること。記録はそのための最小限 |
| 食べたものを全部記録する（食事枠×26カテゴリ） | 決めたことが起きた日だけ押す |
| 食事と便に特化。運動は扱わない | 食事（減らしたいもの）と運動（続けたいこと）、便 |
| 押していない日は「未記録」と示し、断定しない | 押していない日は「食べなかった」「やっていない」と言い切る |
| 評価しない・褒めない（Surface） | 良し悪しは自分で決めて見せ、連続日数で励ます。ただし責めない |
| 週カレンダーが中心 | 月カレンダーが中心 |

PWA、オフラインでの記録、Firebase、判子の見た目（「日めくり × 判子」）といった土台は引き継ぐ。初版のコンセプト「日々を、押していく」は、意味のある日だけ押すことで、むしろ強まる。
